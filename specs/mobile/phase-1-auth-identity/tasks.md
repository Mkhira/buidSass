## Block A — Foundation (no UI yet)

### T-1.1 · core/error types
- **Goal:** sealed `Failure` hierarchy + `ErrorMapper`.
- **Files:** `lib/core/error/failure.dart`, `lib/core/error/error_mapper.dart`.
- **Steps:**
  1. Create `Failure` sealed class with subtypes: `ValidationFailure(fields)`, `AuthFailure`, `ForbiddenFailure`, `ConflictFailure`, `NotFoundFailure`, `ServerFailure`, `NetworkFailure`, `OfflineFailure`. Each carries `message`, `correlationId`, optional `details`.
  2. Create `ErrorMapper.fromDio(DioException)`. Map by status code AND by `error.code` body field. Network/timeout/cancel → `NetworkFailure` / `OfflineFailure`.
  3. Pull `correlationId` from `response.data.error.correlationId` falling back to `RequestOptions.headers['X-Correlation-Id']`.
- **DoD:** unit tests for each branch + a parameterized table test over 401/403/409/422/429/500/network/cancel.

### T-1.2 · core/session
- **Goal:** `SessionStore` + `SessionState`.
- **Files:** `lib/core/session/session_store.dart`, `lib/core/session/session_state.dart`.
- **Depends on:** —
- **Steps:**
  1. `SessionState` sealed with `Unknown`, `Anonymous`, `Authenticated(profile, locale, market)`.
  2. `SessionStore` backed by `flutter_secure_storage`. Methods: `loadOnBoot()`, `persistSession(accessToken, refreshToken, profile)`, `persistLocale(locale, market)`, `clear()`, `Stream<SessionState> stateStream`.
  3. Single instance via DI registration in `app_module.dart`.
- **DoD:** unit tests: load empty, load present, persist + reload across instance, clear leaves Anonymous.

### T-1.3 · core/api Dio + interceptors (verify + complete)
- **Goal:** Dio factory ready for IDN alias; all five interceptors operational.
- **Files:** existing `dio_factory.dart`, `auth_interceptor.dart`, `locale_market_interceptor.dart`, `correlation_id_interceptor.dart`, `idempotency_interceptor.dart`.
- **Depends on:** T-1.1, T-1.2.
- **Steps:**
  1. Audit existing files; bring under §4.1 spec requirements.
  2. `DioFactory.forAlias(ApiAlias.identity)` returns `Dio` with base URL from env, interceptors registered in order: correlationId → localeMarket → auth → idempotency → ErrorMapper transformer.
  3. Auth interceptor: on 401 with `error.code != "invalid_credentials"`, attempt single refresh; on success retry the original request once; on 2nd 401 clear store and emit `SessionState.anonymous`.
  4. Idempotency interceptor: only attaches header to ops listed in `lib/core/api/idempotency_opted_in.dart` (constant set sourced from §6 matrix). Key generated by intent, not by request — see `idempotency_interceptor.dart` design.
- **DoD:** integration test with mocked HTTP server: header presence, refresh-on-401, error mapping.

### T-1.4 · features/identity folder consolidation
- **Goal:** move existing `features/auth/**` → `features/identity/**` so all identity surfaces share a folder.
- **Depends on:** T-1.3.
- **Steps:**
  1. Rename folder.
  2. Update imports across `apps/customer_flutter/lib/**` and tests.
  3. Add `lib/features/identity/data/identity_gateway.dart` (interface) + `identity_gateway_impl.dart`.
  4. Generate DTOs from `openapi.identity.json` (manual hand-written DTOs allowed — no generator dependency in Phase 1; declare in `models/`).
- **DoD:** repo compiles; existing widget tests still pass.

### T-1.5 · core/theme + core/widgets
- **Goal:** brand palette tokens, AR + EN themes, reusable widgets (error banner, empty state, loading skeleton, conflict dialog).
- **Files:** `lib/core/theme/colors.dart`, `lib/core/theme/app_theme.dart`, `lib/core/theme/text_directionality.dart`, `lib/core/widgets/*`.
- **Depends on:** —
- **Steps:**
  1. `colors.dart` exports `kBrandPrimary = Color(0xFF1F6F5F)` etc.; semantic `kSuccess`, `kWarning`, `kError`, `kInfo` per design system.
  2. `app_theme.dart` returns `ThemeData` with palette applied; one method per locale: `themeAr()`, `themeEn()`.
  3. `ErrorBanner({required Failure failure})` widget — copies correlation-id to clipboard on long-press.
  4. `ConflictDialog({required String oldSummary, required String newSummary, required VoidCallback onAccept, required VoidCallback onReview})` — reused by Phase 4 checkout drift.
- **DoD:** golden tests on the four widgets in both locales.

### T-1.6 · core/router + redirect guard
- **Goal:** `go_router` configured with the route table from `plan.md`, redirect guard wired to `SessionStore.stateStream`.
- **Files:** `lib/core/router/app_router.dart`, `lib/core/router/redirect_guard.dart`.
- **Depends on:** T-1.2, T-1.5.
- **Steps:**
  1. Define all routes from `plan.md`. Public routes outside the shell; protected routes inside the bottom-nav shell.
  2. Redirect guard reads `SessionState`. On `Unknown`, route to `/`. On `Anonymous` + protected, stash `redirectTo` and route to `/login`. On `Authenticated` + public, route to `redirectTo` else `/home`.
  3. Bottom nav for protected shell (Home / Categories / Cart / Orders / More).
- **DoD:** integration test: unauthenticated user hitting `/orders/123` is redirected to `/login?redirectTo=/orders/123`, and after login lands on `/orders/123`.
